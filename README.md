# Roadmap Lab

A personal Android app that turns the career roadmap (AI skills + SAP S/4HANA Finance) into a 3-minute daily routine.
Version 1 of the *Roadmap Tracker App: Design and Build Brief* (14 Nov 2026).

**Setup and install: see [SETUP.md](SETUP.md).**

## What's in version 1

| Screen | What it holds |
|---|---|
| Today | Motivation line, "you are here" line, mood and energy (1–5) + sleep, up to 3 tasks with Learn / Apply / Done when, done / partly / skipped with minutes, if-then plan, evening log with notes and evidence line |
| Review | Due questions: multiple choice, then flashcards after 2 correct answers; Again / Hard / Good / Easy; Leitner boxes; max 20 a day; topics mixed |
| Plan | Timeline Oct 2026 – Dec 2027 with Today and You markers, ahead/behind, 4 track bars, milestones, phases with every task |
| Journal | Numbered daily logs (Log #042 · 14 Nov 2026 · 21:40) with the evidence log; searchable |
| Settings | Mode (India / DRC / heavy week), reduced plan, reminder time, theme, Back up to Drive, Restore, roadmap and cards import, version |

Calm rules: max 3 tasks a day sized to the mode; unfinished tasks move to the next free slot; Restart view after 3+ missed days;
max 20 reviews a day; one free miss per week for the streak; reduced plan offered beyond 14 days behind (never red);
at most one reminder a day, only if the evening log isn't done.

## How it's built

- Kotlin + Jetpack Compose (Material 3), minSdk 26, targetSdk 35
- Room (SQLite) for plan, logs and card progress; DataStore for settings
- Charts drawn with Compose Canvas; IBM Plex Sans + Mono (SIL OFL, see `licenses/`)
- No internet permission. Backups go through Android's file picker (choose Google Drive). Android auto backup is on as a safety net.
- `app/src/main/assets/roadmap.json` and `cards.json` are generated by `tools/build_content.py` from the roadmap PDF.
- Logic tests in `app/src/test` run on every build (planner, progress / "you are here", reviews, streak, backup round trip).

## Safe updates

- Every APK is signed with the same key (GitHub Secrets; backup copy in your private Drive).
- `version.properties` sets the version; `versionCode` is derived from it and always increases.
- Every database change gets a `Migration` in `LabDatabase.MIGRATIONS`. Destructive migration is never used.

## Releasing a new version (for Claude)

1. Change `VERSION_NAME` in `version.properties` (e.g. `1.0.1`).
2. Commit and push to `main`.
3. GitHub Actions builds the signed APK and publishes release `v1.0.1` with the APK attached (once per version).
